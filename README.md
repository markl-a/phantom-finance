# phantom-finance

[![phantom-mesh ecosystem](https://img.shields.io/badge/ecosystem-phantom--mesh-purple)](https://github.com/markl-a/phantom-mesh)

A local-first, command-line personal finance tracker: import a bank CSV (zh or
en), auto-categorize transactions with keyword rules, set monthly budgets, and
generate a plain, shame-free monthly report. All data stays on your machine
under `~/.phantom-mesh/`. It is the finance piece of the
[phantom-mesh](https://github.com/markl-a/phantom-mesh) ecosystem and writes an
event file per report so other components can consume it.

## What it does

- **JSONL ledger** — append-only, amounts are `Decimal` end-to-end (floats are
  rejected at the boundary, so no rounding drift). Each transaction gets a
  sha256 `txn_id`, so re-importing the same statement is idempotent (duplicates
  are skipped).
- **CSV import** — auto-detects English and Chinese column headers
  (`Date/Amount/Description`, `交易日期/金額/摘要`, …), handles a UTF-8 BOM,
  normalizes `2026/6/1` / `20260601` dates to ISO, and parses `NT$1,234` /
  `1,234.56` amounts. Signed amounts: negative = expense, positive = income.
- **Rule categorizer** — substring keyword rules covering both Chinese and
  English merchant names (groceries, dining, transport, utilities, housing,
  subscription, health, entertainment, income, transfer). Unknown expenses stay
  `uncategorized`; unknown positive amounts are treated as income by sign.
  There is also an *optional* `LlmCategorizer` callable hook for the
  rules-miss case — see the honest status note below.
- **Monthly budgets** — set a per-category limit, see spent / limit / ratio with
  an "over plan" flag. `transfer` transactions are excluded from spend totals.
- **Shame-free monthly report** — a markdown report that states numbers without
  judgement (`over plan — worth a look`, never "you overspent"). Written to
  `~/.phantom-mesh/logs/phantom-finance/<month>-report.md`, and a matching event
  is emitted to `~/.phantom-mesh/events/`.

See [`docs/sample-month-report.md`](docs/sample-month-report.md) for real output
generated by the demo from the bundled fixtures.

## Quickstart

```bash
git clone https://github.com/markl-a/phantom-finance
cd phantom-finance
pip install -e .

# Manual entry (negative = expense, same sign convention as bank CSVs)
phantom-finance add -- -120 "全聯 weekend groceries"

# Import a bank statement (zh/en headers auto-detected, re-imports deduped)
phantom-finance import statement.csv --account cathay

# Set a budget, check this month's status
phantom-finance budget set dining 6000
phantom-finance budget show

# Write the monthly report (also emits a mesh event)
phantom-finance report --month 2026-06
```

The fastest way to see the whole pipeline end to end — import → budget →
report — against the bundled bilingual fixtures (no real data, fully sandboxed):

```bash
pip install -e .
./examples/demo.sh          # runs import/budget/report, prints the report
./examples/demo.sh --save   # also regenerates docs/sample-month-report.md
```

`examples/demo.sh` runs entirely inside a temporary directory (via the
`PHANTOM_MESH_HOME` / `PHANTOM_FINANCE_HOME` env vars), so it never touches your
real `~/.phantom-mesh/`.

Run the tests:

```bash
pip install -e '.[test]'
pytest -v
```

## How it works & honest status

```
bank CSV / manual add
        |
        v
  ingest.py ──> categorize.py (rules) ──> ledger.jsonl (JSONL, Decimal, dedupe)
                                              |
                          +───────────────────+───────────────────+
                          v                                       v
                    budget.py (monthly budgets)         reporter.py (monthly report)
                                                                  |
                                          +───────────────────────+
                                          v                       v
                  ~/.phantom-mesh/logs/phantom-finance/   ~/.phantom-mesh/events/
```

Design principles: **local-first** (no cloud, no upload; `.gitignore` blocks
`ledger.jsonl` / `*.csv` to prevent accidental commits of real data),
**Decimal end-to-end** (floats raise `TypeError` at the boundary), and
**shame-free by construction** (no judgemental templates exist, and a test
enforces it).

What is **not** done yet (honest caveats):

- **The LLM categorizer is an unwired hook.** `categorize.py` defines an
  optional `LlmCategorizer` callable and `categorize_one(..., llm=...)` will call
  it as a fallback when no keyword rule matches — but no code path
  (CLI, import) ever passes one, so by default **no LLM is invoked**.
  Categorization is 100% keyword rules today. The hook signature is stable so a
  model router can be wired in later; until then, unmatched expenses simply stay
  `uncategorized`.
- Categorization is rule-based, so an unseen merchant name stays
  `uncategorized` until you add a keyword or re-run `recat`.
- `transfer` detection is also rule-based; double-check categories before
  reading totals if you move large amounts between accounts.

See [`docs/ROADMAP.md`](docs/ROADMAP.md) for the planned Tier 2 / Tier 3 work
(wiring the LLM hook, TW bank CSV presets, recurring-charge detection,
multi-currency).
